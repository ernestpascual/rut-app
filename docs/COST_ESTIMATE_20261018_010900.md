## 3. Recalibrated Unit Economics with Gemini 3.5 Flash Lite

### Action A: Save & Auto-Index Inspiration (`onInspirationWritten`)
*Automatically triggered upon dumping an item (URL, Instagram reel, note, Pinterest save, or photo).*

1. Cloud Function execution: `0.4 µs`
2. SSRF-protected metadata scrape (OpenGraph / HTML preview, max 256KB): `0.0 µs`
3. Gemini 3.5 Flash Lite summarization & tagging (~350 prompt tokens, ~80 output tokens):
   - Input: `(350 / 1000) * 38 µs` = `13.3 µs`
   - Output: `(80 / 1000) * 150 µs` = `12.0 µs`
4. `text-embedding-004` vector generation (~1,200 characters):
   - Embedding: `(1200 / 1000) * 25 µs` = `30.0 µs`
5. Firestore writes (doc update, index vector, usage ledger): 5 writes = `9.0 µs`

> **Total Cost per Saved Item:** **64.7 µs (~$0.000065 USD)**  
> *Scale Benchmark:* **~15,400 items saved per $1.00 USD** *(28% cheaper than 3.6 Flash)*.

### Action B: "Chat with Bank" Multi-Turn Turn ([`chatWithBank.ts`](file:///Users/ernest.pascual/Downloads/Development/rut/functions/src/callable/chatWithBank.ts))
*Interactive RAG brainstorming turn grounded in private bank pins, real-time Firestore bank counting, candidate retrieval (up to 5 items), and conversation history.*

1. Cloud Function invocation: `0.4 µs`
2. Firestore candidate retrieval, bank counting & session context:
   - Session doc, active pins, conversation history: ~10 reads = `6.0 µs`
   - Direct Firestore candidate bank pool (up to 80 non-archived items): amortized ~20 reads = `12.0 µs`
   - Real-time `count().get()` aggregation query: 1 read = `0.6 µs`
   - Subtotal Firestore reads: `18.6 µs`
3. Query embedding for semantic reranking ([`retrieval.ts`](file:///Users/ernest.pascual/Downloads/Development/rut/functions/src/ai/retrieval.ts), `text-embedding-004`, ~120 chars): `3.0 µs`
4. Gemini 3.5 Flash Lite inference (~1,250 prompt tokens with memory, history, and up to 5 candidate snippets; ~500 output tokens typical, up to 2,500 max):
   - Input: `(1250 / 1000) * 38 µs` = `47.5 µs`
   - Output (typical 500 tokens): `(500 / 1000) * 150 µs` = `75.0 µs`
   - *(At maximum 2,000 words / ~2,500 tokens: output = `(2500 / 1000) * 150 µs` = `375.0 µs`)*
5. Firestore write (assistant response message, usage event logging): 4 writes = `7.2 µs`

> **Typical Cost per Chat Turn:** **151.7 µs (~$0.000152 USD)**  
> **Max Cost per Chat Turn (2,000 words):** **451.7 µs (~$0.000452 USD)**  
> *Scale Benchmark:* **~6,590 typical chat turns per $1.00 USD** *(45% savings vs 3.6 Flash)*.

## 7. Built-in Cost Safeguards & Guardrail Architecture

To protect against cost overruns, accidental loops, or scraping attacks, `rut` enforces five multi-layer circuit breakers:

1. **Daily User Spending Cap:**  
   [`functions/src/cost/ledger.ts`](file:///Users/ernest.pascual/Downloads/Development/rut/functions/src/cost/ledger.ts) checks daily usage before every Gemini invocation. Accounts are strictly blocked from exceeding **$2.00 / day (2,000,000 µs)**.
2. **Request Rate Limiting:**  
   Maximum **500 AI requests per user per day**.
3. **Content Hash Deduplication:**  
   Items compute a SHA-256 equivalent `contentHash`. Renaming tags, reorganizing collections, or updating non-critical fields skips re-embedding entirely.
4. **Instant Emergency Kill Switch:**  
   The Firestore document `_systemConfig/global` contains `killSwitchEnabled: true`, which halts all AI processing globally within milliseconds without requiring code deployments.
5. **Zero Storage Policy:**  
   By persisting image URLs instead of downloading and hosting user media binaries in Cloud Storage, `rut` avoids terabytes of storage fees and egress bandwidth bills.
6. **Token-Constrained RAG Grounding:**  
   Candidate retrieval in `chatWithBank` injects up to 5 representative candidate inspirations, truncated to 160 characters each (`~200 tokens`), keeping RAG grounding overhead under 0.008 cents per turn while delivering rich context and true bank size awareness.
